# PCを操作する Claude への依頼

この文書は、Windows PC を操作する Claude に読ませるためのものです。ユーザーは、次のように伝えるだけです。

> duo-remote のリポジトリで git checkout main と git pull をして、docs/pc-requests.md を読んで、依頼C をやってください。

名前を言われた依頼だけを、やってください。今ある依頼は、次の3つです。

| 依頼 | 中身 | いつ |
|---|---|---|
| C | iPhone で試すあいだの、サーバーの起動と見守り | ユーザーが iPhone で試すとき |
| D | 日本語入力（IME）の切り替えの確認 | いつでも |
| J | 自動起動と、git の方式の更新の確認 | PC を再起動してよいとき、新しい版が出たとき |
| K | マウスが動かないときの切り分け | iPhone でタップしても、PC のマウスが動かないとき |

（依頼A、B、E〜I は、確かめ終わったので消した。結果は docs/tasks.md にある。名前は、前の報告と食い違わないよう、そのまま使っている）

リポジトリは `%USERPROFILE%\duo-remote` にあります（なければ `git clone https://github.com/nexon1101-pixel/duo-remote.git`）。

## 共通の決まり

- コードは書き換えない。GitHub に push しない
- サーバーのトークンは、報告に書かない
- 管理者の確認画面（UAC）は、あなたは操作できない。出たら、ユーザーに「許可を押してください」と伝えて、待つ
- サーバーは、強制的に止めない（仮想モニターが有効のまま残る）。黒い画面（start.bat）なら Ctrl+C、管理画面なら「停止」か「管理画面を終了」で止める
- 途中で止まったら、先に進まず、出たメッセージをそのまま報告する
- サーバーの管理画面（`server\panel.bat`）は、Edge で開くと、あなたは触れない。`panel.bat --browser chrome` として Chrome のタブで開き、Claude in Chrome で操作する（管理画面がもう動いているときも、同じコマンドで、Chrome で開き直せる）
- メモ帳を置く、check.bat を呼ぶ、などは、スクリプトで行ってよい。`check.bat` は `python -m duo_server.selfcheck` を直接呼んでもよい。画像やファイルは、あなたが読める場所に保存する
- 始める前に、`server\duo_server\__init__.py` の版を控えて、報告に書く

## 依頼C: iPhone で試すあいだの、サーバーの起動と見守り

目的: ユーザーが iPhone で試しているあいだ、サーバーを管理者で動かし続け、終わったあとの後片付けを確かめる。

### 手順

1. 動いているサーバーと管理画面を止める
2. 最新にする（`cd /d "%USERPROFILE%\duo-remote"`、`git checkout main`、`git pull`）
3. `server\panel.bat --browser chrome` で管理画面を開く。「管理者ではありません」と出ていたら、「管理者として起動し直す」を押す（仮想ディスプレイに要る。UAC はユーザーに押してもらう）
4. 右上が「動いています」になり、ログに「仮想ディスプレイ: 使えます」が出ていること
5. 「つなぎ方」の「家の Wi-Fi・有線ならこれ」のアドレスと、ポートを、ユーザーに伝える（トークンは伝えない。ユーザーが自分で見る）
6. 管理画面は、閉じずに、そのまま動かしておく。ユーザーが「終わった」と言うまで、待つ
   - 待っているあいだ、ユーザーに頼まれたときだけ、管理画面のログを読んだり、`virtual.bat monitors` を実行したりする

### ユーザーが「終わった」と言ったら

1. ユーザーが「切断した」と言ってから **10秒待って**、`server\virtual.bat monitors` を実行する。`【仮想】` が、あるか、ないかを控える
2. `server\duo_server.log` の最後の80行を控える（トークンは伏せる）
3. 管理画面の「管理画面を終了」で止める。止めたあと、もう一度 `virtual.bat monitors` を実行して、控える

### 報告の形

```
・版
・切断のあと10秒たったときの、仮想モニターの有無
・duo_server.log の最後の80行（そのまま）
・止めたあとの、仮想モニターの有無
・ユーザーに頼まれて行ったこと（あれば）
```

## 依頼D: 日本語入力（IME）の切り替えの確認

目的: iPhone の「半角/全角」キーと、IME の切り替えボタンは、サーバーに `ime`（オン・オフ）を送る。それで、PCの IME の状態が、本当に切り替わるかを確かめる。

### 準備

1. 動いているサーバーと管理画面を止める
2. 最新にする（`cd /d "%USERPROFILE%\duo-remote"`、`git checkout main`、`git pull`）
3. メモ帳（Notepad）を開く。**メモ帳に、日本語入力（Microsoft IME）が使える状態にしておく**（右下の言語表示が「あ」か「A」になっていること。「ENG」のままなら、日本語のキーボードに切り替える）。タイトルに含まれる文字を控える（日本語の Windows なら「メモ帳」）
4. `server\start.bat` でサーバーを起動する

### 確認

別のコマンドプロンプトで、次を実行する。

```bat
cd /d "%USERPROFILE%\duo-remote\server"
check.bat --ime --title メモ帳
```

- 次の2つの `[OK]` が出るはず
  - IMEをオンにできました（PCのIMEの状態が、オンになった）
  - IMEをオフにできました（PCのIMEの状態が、オフになった）
- 出力を全部控える
- 実行中、メモ帳が前に出る。そのとき、画面の右下の言語表示（「あ」と「A」）が、切り替わったかを見て、報告する（スクリーンショットが撮れるなら、撮る）

### 後片付け

サーバーの画面で Ctrl+C を押して止める。メモ帳は保存せずに閉じる。

### 報告の形

```
## 版

## check.bat --ime の出力
（そのまま）

## 言語表示（「あ」と「A」）は、切り替わったか

## duo_server.log の最後の40行
（そのまま。トークンは伏せる）

## そのほか気づいたこと
```

期待する結果: 2つとも `[OK]`。`[NG]` のときは、メモ帳の IME が日本語入力になっているかを、先に確かめて、もう一度試す。

## 依頼J: 自動起動と、git の方式の更新の確認

2つの確認は、行える時期が違う。ユーザーに言われた方だけを行う。

### J-1: ログインしたときの自動起動（PC を再起動してよいときだけ）

目的: 管理画面の「ログインしたときに自動で起動する」をオンにしてあると、Windows にログインしたときに、管理画面とサーバーが、画面を出さずに動き出すことを確かめる。

1. **PC を再起動してよいか、ユーザーに聞く。** よいと言われたときだけ進める
2. 自動起動がオンになっていることを確かめる: `schtasks /Query /TN "DuoRemote サーバー"` でタスクがあること
3. 開いているファイルを保存してもらってから、ユーザーに再起動してもらう（あなたが再起動のコマンドを打たない）
4. ログインしたあと、1分ほど待ってから、次を確かめて控える
   - `netstat -ano | findstr ":8765 :8770"` で、両方が LISTENING になっている（サーバーと管理画面）
   - `server\panel.lock` がある
   - 管理画面のウィンドウは、開いていない（自動起動のときは、画面を出さない）
   - `server\panel.bat --browser chrome` で、すでに動いている管理画面が Chrome で開き、右上が「動いています」、管理者欄が「管理者として動いています」であること

### J-2: git の方式の更新（新しい版が出たときだけ）

目的: git で取ったこのリポジトリを、管理画面の「更新」で新しい版にできることを確かめる。GitHub の main の版が、このPCの版より新しいときにしか試せない。

1. このPCの版（`server\duo_server\__init__.py`）を控える。**この依頼では `git pull` をしない**（自分で新しくすると、更新を試せない）
2. `server\panel.bat --browser chrome` で管理画面を開く
3. 「更新」の欄で「確かめる」を押す。「GitHub の版」が今の版より新しく、「更新の方式: git」と出ること。同じなら、試せないので、そう報告して終わる
4. 「更新する」を押し、ページの中の確認で「続ける」を押す
5. 更新のログが出て、少しすると、同じタブが新しい管理画面に切り替わること
6. 新しい管理画面の「今の版」が、GitHub の版と同じになっていること。「前回の更新のログ」を開いて、中身を控える
7. `git log --oneline -1` を実行し、main の新しいコミットになっていることを確かめる

### 報告の形

```
## 版

## J-1: 自動起動（行ったときだけ）
・netstat の出力、panel.lock の有無、ウィンドウが開いていなかったか、管理画面の状態

## J-2: git の方式の更新（行ったときだけ）
・更新の前と後の版、前回の更新のログ（そのまま）、git log の出力、タブが切り替わったか

## そのほか気づいたこと
```

## 依頼K: マウスが動かないときの切り分け

目的: iPhone でタップしても、トラックパッドを使っても、PC のマウスが動かない。原因が、次のどれかを見分ける。
- ア: アプリが、操作をサーバーに送っていない
- イ: サーバーは受け取っているが、Windows が、入力を受け付けていない
- ウ: サーバーから Windows への入力は通るので、アプリの側の問題

### 準備

1. 動いているサーバーと管理画面を止める
2. 最新にする（`cd /d "%USERPROFILE%\duo-remote"`、`git checkout main`、`git pull`）。`server\duo_server\__init__.py` が `0.15.2` 以降であること
3. `server\panel.bat --browser chrome` で、管理画面を開く。「管理者として動いています」と出ていなければ、「管理者として起動し直す」を押す（UAC はユーザーに許可してもらう）

### 確認 1: サーバーから Windows への入力（iPhone を使わない）

別のコマンドプロンプトで、次を実行する。マウスのカーソルが、画面の中を動く。

```bat
cd /d "%USERPROFILE%\duo-remote\server"
check.bat --mouse
```

- 3つの `[OK]` か、`[NG]` が出る。出力を全部控える
- `[NG]`（カーソルが動かない）なら、イ。管理画面のログに、「SendInput が一部しか通りませんでした」か「カーソルが、送った位置に動いていません」が出ていないかを見て、そのまま控える

### 確認 2: iPhone からの操作が届くか（ユーザーが iPhone で行う）

1. 管理画面の「ログ」を開いておく
2. ユーザーに、iPhone で接続して、画面をタップしたり、トラックパッドを動かしたりしてもらう
3. 管理画面のログに、次のどれが出るかを控える
   - 「最初の操作を受け取りました: move」（または button など）→ サーバーは受け取っている
   - 「カーソルが動くことを確かめました」→ Windows にも通っている
   - 「カーソルが、送った位置に動いていません」→ イ
   - どれも出ない → ア（アプリが、送っていない）
4. ユーザーが iPhone の接続を切ったあと、ログに「切断しました（受け取った操作: …）」が出る。その行を、そのまま控える（「なし」か、「move 120、button 4」のような数）

### 報告の形

```
## 版

## 確認 1: check.bat --mouse の出力（そのまま）

## 確認 2: ログに出た行（そのまま。ア、イ、ウのどれに当たるか）

## そのほか気づいたこと
```

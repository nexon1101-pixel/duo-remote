# 通信の取り決め（バージョン1）

iPhoneアプリ（クライアント）とWindowsサーバーの間の通信を定める。変更するときは、この文書とサーバー・アプリの両方を同時に直す。

## つなぎ方

- WebSocket（`ws://<ホスト>:8765/`）を1本だけ使う
- テキストフレーム: JSONの制御メッセージ
- バイナリフレーム: 映像（サーバー→クライアントのみ）
- サーバーは同時に1台のクライアントだけを受け付ける。新しくつながると、前の接続は切られる
- 外出先からは、WindowsとiPhoneの両方にTailscaleを入れ、Tailscaleのアドレスでつなぐ。ポートはインターネットに公開しない

## 認証

最初のメッセージは必ず `hello` にする。5秒以内に届かない場合、またはトークンが違う場合は、サーバーが `error` を返して接続を切る。

トークンは、サーバー初回起動時に作られ、`server/config.json` に保存される。リポジトリには入れない。

## クライアント→サーバー

| t | 項目 | 意味 |
|---|---|---|
| `hello` | `v`（版, 1）, `token`, `fps`（省略可）, `max_height`（省略可） | 接続の開始 |
| `mode` | `mode`（`screen` または `window`）, `id`（windowのとき。`windows` の `id`）, `fit_w`, `fit_h`（省略可） | 表示する範囲の切り替え。下の「ウィンドウ単位の表示」を参照 |
| `list_windows` | なし | ウィンドウ一覧の要求。サーバーは `windows` で返す |
| `move` | `x`, `y`（0〜1） | マウスを動かす |
| `button` | `b`（`left` `right` `middle`）, `d`（`down` `up`）, `x`, `y`（省略可） | ボタンの押下と解放。x, yがあれば先に移動する |
| `scroll` | `dx`, `dy`（ホイールの目盛り数。1.0が1目盛り） | スクロール。`dy` が正で上方向、`dx` が正で右方向 |
| `key` | `vk`（Windowsの仮想キーコード）または `sc`（スキャンコード）, `d`（`down` `up`） | キー操作。下の「キーの送り方」を参照 |
| `text` | `s`（文字列、4096文字まで） | 確定済みの文字を、そのまま入力する。iPhoneのキーボード用 |
| `ime` | `on`（true / false） | IMEのオン・オフ |
| `ping` | `n`（数値） | 往復の確認 |

座標 `x`, `y` は、表示している範囲の左上を(0, 0)、右下を(1, 1)とする。範囲が画面全体ならPCの画面、ウィンドウなら、そのウィンドウ。

## サーバー→クライアント

| t | 項目 | 意味 |
|---|---|---|
| `welcome` | `v`, `w`, `h`（映像の大きさ）, `codec`（`h264`）, `mode` | 認証の成功。この直後から映像が流れる |
| `ime_state` | `on`（true / false） | IMEの状態が変わったときに送る。取れない環境では送らない |
| `pong` | `n` | `ping` への返事 |
| `resize` | `w`, `h` | 映像の大きさが変わった |
| `windows` | `list`（`id`, `title`, `app` の並び） | ウィンドウの一覧。手前にあるものから順に並ぶ。`app` は実行ファイル名（取れなければ空） |
| `mode` | `mode`, `id`, `title`（windowのとき） | 表示する範囲が変わった。`mode` の要求への返事のほか、ウィンドウが閉じられて画面全体に戻したときにも送る |
| `error` | `message` | エラー。認証の失敗時は、続けて切断する |

## 映像（バイナリフレーム）

1つのバイナリフレームが、H.264の1フレーム（アクセスユニット）に当たる。

```
offset 0   : 1バイト  フラグ（bit0 = キーフレーム）
offset 1-4 : 4バイト  タイムスタンプ（ミリ秒、ビッグエンディアン、接続開始からの経過）
offset 5-  : H.264（Annex B形式）
```

- 各フレームの先頭にAUD（NALタイプ9）が付く
- キーフレームには、SPSとPPSが先頭に付く。クライアントは、これを使ってデコーダーを作る
- Bフレームは使わない。キーフレームは約2秒おきに入る
- 映像の大きさは、`welcome` の `w`, `h` と同じ。途中で変わる場合は `resize` を先に送る

## キーの送り方

- `vk`：Windowsの仮想キーコード（1〜254）。iPhoneのキーボードの横に出す Esc、Tab、矢印などに使う
- `sc`：キーの位置を表すスキャンコード。Bluetoothキーボードのキーは、全てこれで送る。どの文字になるかは、PCのキー配列（JIS、USなど）で決まる。拡張キー（矢印、Insert、Delete、右Ctrlなど）は、`0xE0` を上に付けて `0xE04B` の形にする。1バイトの値（1〜255）か、`0xE001`〜`0xE0FF` だけを受け付ける
- 両方あるときは `sc` を使う
- PCは、押したままのキーを自分では繰り返さない。押し続けたときの繰り返しは、クライアントが `down` を何度も送って行う
- 日本語キーボードの「英数」「かな」キーは、`key` ではなく `ime` で送る（「英数」でオフ、「かな」でオン）

## ウィンドウ単位の表示

- `mode` で `window` を選ぶと、サーバーはそのウィンドウを前に出し、ウィンドウの範囲だけを撮る。他のウィンドウが上に重なると、それも映る
- `fit_w`, `fit_h` があれば、先にウィンドウの大きさを変える。iPhoneの画面のポイント数を送ると、1ポイントがWindowsの1論理画素（拡大率をかけた画素）になる大きさにする。作業領域に入らないときは、縦横比を保って縮める
- 返事の順番は、`mode`、`resize`（大きさが変わるときだけ）、新しい映像。新しい映像は、SPSとPPSの付いたキーフレームから始まる
- ウィンドウが動いたり大きさが変わったりすると、サーバーは撮り直し、`resize` を送る（同じ位置が0.5秒続いてから）。最小化している間は、前の範囲のまま
- ウィンドウが閉じられると、`error` と `mode`（`screen`）を送り、画面全体に戻す
- 主モニターからはみ出した部分は撮らない。全く出ていないウィンドウは選べない（`error` を返す）
- 切断すると、範囲は画面全体に戻る

## 切断したとき

- サーバーは、押したまま離されていないマウスのボタンとキーを、すべて離す

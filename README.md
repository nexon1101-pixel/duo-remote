# duo-remote

iPhone Duo から、自宅の Windows PC を操作するアプリです。PCの画面を iPhone に映し、タッチやキーボードで操作します。

- PC側では、サーバー（Python）を動かします。画面を動画にして送り、iPhoneからの操作を受け付けます
- iPhone側では、アプリを入れます

まだ作っている途中です。Windows と iPhone の実機では、まだ動作を確かめていません。

## できること

- PCの画面全体、またはウィンドウ1つだけを、iPhoneに映す
- タッチでマウスを操作する（クリック、ドラッグ、スクロールなど）。トラックパッドのように動かす方式も選べる
- 文字を入力する（iPhoneのキーボード、またはBluetoothキーボード）
- 映像をピンチで拡大する
- PCの音を、iPhoneで鳴らす（オンとオフを切り替えられる）
- 切れたときに、自動でつなぎ直す

## はじめかた

### 1. PCでサーバーを動かす

1. このリポジトリを取ってくる。次のどちらかで取れる
   - git を使う: `git clone https://github.com/nexon1101-pixel/duo-remote.git`
   - GitHub のこのページの「Code」→「Download ZIP」で取り、展開する
2. `server` フォルダの `start.bat` をダブルクリックする
   - 初回は準備に数分かかる。Python や ffmpeg が入っていなければ、入れるかを聞かれるので「Y」と答える
   - Windows のファイアウォールの確認が出たら、「プライベート ネットワーク」を許可する
3. 画面にトークンが表示されるので、控えておく（iPhoneで入力する）
4. PCのIPアドレスを調べる。コマンドプロンプトで `ipconfig` を実行し、Wi-Fi（または有線）の「IPv4 アドレス」を見る（`192.168.x.x` のような形）

サーバーが動いている間は、画面を開いたままにしておきます。閉じるとサーバーも止まります。止めるときは Ctrl+C を押します。

iPhone を使う前に、PCだけでサーバーを確かめられます。サーバーを起動したまま、`server` フォルダの `check.bat` を実行すると、映像が作れているか、ウィンドウの一覧が取れるかを調べて、`[OK]` か `[NG]` で表示します（`check.bat --window` で、ウィンドウ1つだけの表示も、`check.bat --audio` で、PCの音が届くかも試します。音は、PCで何か鳴らしながら実行してください）。PCを操作する Claude に確認を頼むときの手順は、[docs/pc-check.md](docs/pc-check.md) にあります。

### 2. iPhoneにアプリを入れる

1. iPhone の Safari で [最新のビルド](https://github.com/nexon1101-pixel/duo-remote/releases/tag/latest) を開き、`DuoRemote.ipa` を取る
2. SideStore（または Sideloadly）で入れる

無料の Apple ID では、同時に入れられるアプリは3つまでです。

### 3. つなぐ

1. PCとiPhoneを、同じWi-Fiにつなぐ
2. アプリを開き、次を入力して「接続」を押す
   - ホスト: PCのIPアドレス
   - ポート: `8765`
   - トークン: サーバーに表示されたもの
3. 「ローカルネットワーク上のデバイスの検索」の確認が出たら、許可する（許可しないとつながらない）

ホストとポートはアプリに、トークンは iPhone のキーチェーンに保存されるので、次からは「接続」を押すだけです。

## 使い方

画面の右上のボタンで、メニューを開きます。

### 表示

- メニューの「ウィンドウを選ぶ」で、ウィンドウ1つだけを映す。「画面全体を表示」で元に戻る
  - 「この画面に大きさを合わせる」をオンにすると、ウィンドウの大きさを、iPhoneの画面と同じ縦横比に変える。文字は、PCで見るのとほぼ同じ大きさになる。iPhoneを回したり、Duoを閉じたり開いたりしたときも、合わせ直す
  - 選んだウィンドウは前に出る。他のウィンドウが上に重なると、それも映る
  - ウィンドウを動かすと、表示もついていく。閉じると画面全体に戻る
- ピンチで映像を拡大・縮小する（iPhoneの中だけで、PCには送らない）。拡大中は、2本指で動かすと映像が動く。元の大きさまで縮めると、拡大が解ける

### 画面の触り方

メニューの「操作の設定」で、2つの方式から選びます。

| 操作 | 直接触る（初期値） | トラックパッド |
|---|---|---|
| タップ | その場所を左クリック（続けて2回でダブルクリック） | カーソルの場所を左クリック |
| 1本指で動かす | 左ボタンを押したまま動かす | カーソルを動かす（クリックはしない） |
| 長押し | 右クリック | 長押ししてから動かすと、左ボタンを押したまま動かす |
| 2本指でタップ | 右クリック | 右クリック |
| 3本指でタップ | 中ボタンのクリック | 中ボタンのクリック |
| 2本指で動かす | スクロール（指を離したあとも少し流れる） | 同じ |
| ピンチ | 映像の拡大・縮小 | 同じ |

トラックパッドの方式では、クリックせずにカーソルを動かせるので、マウスを乗せると出る説明やメニューも出せます。

### 文字の入力

メニューの「入力」で、3つの方式から選びます。

| 方式 | 内容 |
|---|---|
| タッチだけ | マウスの操作だけ |
| iPhoneのキーボード | iPhone側で変換まで済ませ、確定した文字をPCに送る |
| Bluetoothキーボード | キーをそのままPCに送る。日本語の変換はPCのIMEで行う |

- 右下のボタンで、iPhoneのキーボードを出したり、しまったりできる。PCのIMEの状態（あ / A）も、ここに出る
- iPhoneのキーボードの上には、Ctrl、Shift、Alt、Win、Esc、Tab、矢印、Home、End、BS、Del、Enter、IMEの切り替えのキーが並ぶ
  - Ctrl、Shift、Alt は、先に押しておくと、次に打った英字・数字か、次に押したキーと一緒に押したことになる（Ctrl+C、Shift+→ など）
- Bluetoothキーボードをつなぐと、自動でBluetoothキーボードの方式になる。外すと、タッチだけに戻る
  - 日本語キーボードの「英数」「かな」キーで、PCのIMEがオフ・オンになる
  - Macのキーボードの command キーは、PCでは Windowsキーになる。メニューの「操作の設定」で「command を Ctrl にする」をオンにすると、Ctrl になる
  - command+Tab、command+スペース、地球儀キーなど、iPhoneが先に使う組み合わせは、PCに届かない

### 音

- メニューの「PCの音を鳴らす」で、オンとオフを切り替える。初期値はオフ
- **オンにすると、iPhoneで再生中の他のアプリの音（YouTube など）は止まる**。オフに戻すと、他のアプリが続きを再生できる状態に戻る
- 「他のアプリの音と混ぜる」をオンにすると、他のアプリの音を止めずに、PCの音を重ねて鳴らす
- オフのときは、アプリは音に何も触らない
- 音は、圧縮せずに送る。帯域は、高・中の画質で約 1.5Mbps、低の画質（24000Hz、モノラル）で約 0.4Mbps
- PCが無音のときは、何も送らない。PCで音を鳴らしたときだけ、届く
- 音は、アプリを開いている間だけ鳴る。裏に回すと、接続が切れて、音も止まる
- 映像との時間のずれを合わせる処理は、まだない。音が少し遅れて聞こえることがある

### 接続が切れたとき

- 自動で6回までつなぎ直す。つなぎ直したら、見ていたウィンドウの表示に戻る
- 通信が静かに途切れたとき（Wi-Fi が切れたなど）も、10秒ほどで気づいて、つなぎ直す
- アプリを裏に回すと、接続を閉じる。戻ると、つなぎ直す
- 別の端末がつながって切られたときは、つなぎ直さない
- 押したままだったマウスのボタンやキーは、サーバーが離す

### 画質と遅れ

- 画質は、接続の画面か、メニューの「操作の設定」の「画質」で選ぶ。接続中に変えると、つなぎ直す

  | 画質 | 映像の高さ | ビットレート | フレームレート |
  |---|---|---|---|
  | 高（初期値） | 元の大きさ | 8000kbps | 60fps |
  | 中 | 1080 | 4000kbps | 60fps |
  | 低 | 720 | 1500kbps | 30fps |

- メニューに、PCとの往復の時間（遅れ）が出る
- 通信が追いつかないときは、サーバーが古い映像を捨てて、遅れがたまらないようにする（そのとき、最大2秒ほど映像が止まる）
- 接続中は、iPhoneの画面が自動でロックされない

## 外出先から使う

PCとiPhoneの両方に [Tailscale](https://tailscale.com/) を入れ、同じアカウントでログインします。アプリのホストには、PCの Tailscale のアドレス（`100.x.x.x`）を入力します。

ルーターのポートは開けないでください。インターネットから、誰でもPCにつなごうとできるようになります。

## うまくいかないとき

| 困ったこと | 確かめること |
|---|---|
| つながらない | PCとiPhoneが同じWi-Fiにいるか（ゲスト用のWi-Fiだと、端末どうしがつながれないことがある）。PCのファイアウォールで、ポート8765が許可されているか。iPhoneの「設定」→「プライバシーとセキュリティ」→「ローカルネットワーク」で、DuoRemote がオンか |
| ファイアウォールで許可したのに、つながらない | PCの Wi-Fi が「パブリック ネットワーク」になっていると、「プライベート ネットワーク」の許可だけでは通らない。Windowsの「設定」→「ネットワークとインターネット」→「Wi-Fi」（または「イーサネット」）→ 使っているネットワーク →「ネットワーク プロファイルの種類」を「プライベート」にする。または、ファイアウォールでパブリックも許可する |
| しばらくすると切れる | PCがスリープすると、接続が切れる。スリープしたPCを、iPhoneから起こすことはできない。Windowsの「設定」→「システム」→「電源」で、スリープするまでの時間を長くするか、「なし」にする |
| 映像と操作の位置がずれる（モニターが2枚以上） | 撮っているモニターが、主モニターと違うことがある。`start.bat --output-idx 1` のように番号を変えて起動する |
| トークンが違うと言われる | サーバーを `start.bat --show-token` で起動すると、トークンをもう一度表示する |
| 映像が出ない | サーバーの画面に出ている ffmpeg のエラーを見る |
| 一部のウィンドウが操作できない | 管理者として動いているアプリ（タスクマネージャーなど）は、サーバーも管理者として起動しないと操作できない |
| ロック画面やUACの確認画面が操作できない | Windowsの制限で、操作できない |

## まだできないこと

- 主モニター以外のモニター
- 他のウィンドウが上に重なったとき、それを映さないこと
- PCとiPhoneの間のクリップボードの共有
- Windowsにログインしたときに、サーバーを自動で起動すること

## サーバーのオプション

コマンドプロンプトで `start.bat --fps 30` のように付けます。

| オプション | 意味 |
|---|---|
| `--port` | ポート（初期値 8765） |
| `--fps` | フレームレート（初期値 60） |
| `--bitrate` | ビットレート（kbps、初期値 8000） |
| `--max-height` | 映像の高さの上限。0で元の大きさ。通信が細いときは 1080 や 720 にする |
| `--encoder` | `auto`（初期値）、`h264_nvenc`、`libx264`。`auto` は、グラフィックボード（NVENC）が使えればそれを使う |
| `--output-idx` | 撮るモニターの番号（初期値 0）。モニターが2枚以上で、映像と操作がずれるときに変える |
| `--show-token` | トークンを表示する |

`--fps`、`--bitrate`、`--max-height` は、アプリで画質を選ぶと、アプリの値が使われます。

設定は `server/config.json` に保存されます。トークンが入っているので、人に見せたり、コミットしたりしないでください（`.gitignore` に入れてあります）。

| `docs/` | 計画と通信の取り決め |

### サーバーを自分で動かす

```powershell
cd server
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m duo_server
```

ffmpeg は、NVENCを使うため、`full` 版のビルドを使います（例: `winget install Gyan.FFmpeg`）。PATHに通すか、`--ffmpeg` でパスを指定します。

### サーバーのテスト

```bash
cd server
pip install -r requirements-dev.txt
python -m pytest
```

Windows以外でも動きます。画面の取得（ddagrab）と入力（SendInput）は、Windowsでしか動かないため、テストには含まれません。GitHub Actions（`.github/workflows/server-test.yml`）で、Linux と Windows の両方で回しています。

### 版の上げ方

サーバー（`server/duo_server/__init__.py` の `__version__`）とアプリ（`ios/project.yml` の `MARKETING_VERSION`）の版は、そろえておく。上げるときは、両方を同時に変える。アプリの `CURRENT_PROJECT_VERSION` も、1つ上げる。

### iPhoneアプリのビルド

Macがないため、GitHub Actions（`.github/workflows/ios-build.yml`）でビルドします。`ios/` を変えて push するか、「Actions」の「iOS build」から実行すると動きます。

- iPhone Duo の内側画面いっぱいに表示するため、`xcode-27` のランナーで、入っている中でいちばん新しい Xcode（iOS 27.1 以降の SDK）を使う。それより前の SDK でビルドすると、内側画面では iPhone 用の枠（左右が黒）で表示される。使った SDK は、ビルドの「使ったSDKを確かめる」に出る
- できた ipa は、「Releases」の「最新のビルド」（latest）に置く（毎回上書き）。ビルドの画面の「Artifacts」にもある
